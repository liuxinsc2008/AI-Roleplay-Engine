# 目标结构（拆法）

> **2026-10-15 深夜**。定义"文件该怎么分"，不是"现在改成什么样"。
> **⛔ 落地前先确认没有作业在跑** —— 回测脚本读的就是这些路径。

---

## 0 三句话

```
① 变化大的在外，变化小的在内
② 一个文件管一个东西，各自留接口
③ ★ 唯一对外的面 = `interface.py`（facade）——
     而它是【启动时自检】，不是一个转发器
```

$$\textbf{依赖只能向内}：\text{外层可以 import 内层};\qquad \text{内层【不许】import 外层}$$

## 3 每个文件留的接口

```python
# engine/coordinates.py
class Coordinates:
    def reset(self) -> None
    def expose(self, need: str) -> None            # accepted/ignored/punished/none/suppressed
    def apply_time(self, tau_eff: float) -> None   # s_target = params.baseline
    def snapshot(self) -> dict

# engine/alone.py
class AloneChain:
    def step(self, segment: int, dt_eff: float) -> None
    def rate(self, pull: float) -> float           # 速率 = 系数 × pull

# engine/arc.py
class Arc:
    def feed_tension(self, pain: float, pull: float, dt_eff: float) -> None
    def try_transition(self, ctx) -> Optional[str]
    @property
    def stage(self) -> int

# params/
def load(name: str = "default") -> Params          # ★ 缺一个键就报错，不给默认值
# prompts/
def render(name: str, **fields) -> str             # ★ 占位符缺一个就报错，不静默
# characters/
def load(name: str) -> dict
```

## 4 facade：`interface.py`

```python
class Engine:
    @classmethod
    def create(cls, character="hua", params="default", prompts="default") -> "Engine"
    def turn(self, text: str, initiator: str = "他") -> TurnResult
    def state(self) -> StateView        # 坐标 + 弧光 + 规则
    def reset(self) -> None
    def config(self) -> dict            # ★ 含"生效的是哪一份 params / prompts"
    def debug(self) -> dict             # ★ 开发者视图（玩家侧不许用）
```

**⇒ 它直接解掉今晚反复出现的两个病：**

```
① ★ "生效的是哪一份"变成可查询的事实
   ⇒ 今晚六次"两处口径打架"里，至少三次是"不知道生效的是哪一份"

② ★★ "存在 ≠ 接线"有了结构性验收点：
    facade 启动时【自检】—— 背后每个模块的 public 方法必须登记在案
    ⇒ 今晚那张 PENDING 名单 + 接线计数，正好搬进 facade 的启动检查
    ⇒ ★ 那就是 SPEC §H.2 那条"函数在 ≠ 已接线"的解药

③ ★ `client.py` / `shell_server.py` / 回测脚本 只依赖 facade
   ⇒ 换 params · 换 prompts · 换卡 ⇒ 它们一行都不用改
```

## 5 ★★ 四条守卫测试 —— 拆的收益全靠它们

```
① ★★ 单一来源：代码里不许出现字面量系数
      （一组固定系数）⇒ 出现就红
      ⇒ 否则"拆开"只变成"多了一份可以漂的副本"

② ★★ 依赖方向：内层 import 外层 ⇒ 红
      ⇒ 加一个 import 扫描（engine/ **不许** 出现 pipeline/ · io/）

③ ★★ 接线：engine / pipeline 的每个 public 方法
      **必须能从 facade 到达** —— 否则红
      ⇒ 今晚那张 PENDING（待接）名单就是它的第一版

④ ★ 模板占位符：prompts.render 缺占位符 ⇒ 报错，不静默
      （对应"缺失一律 None，绝不猜"——这里是"缺了就别渲染"）
```

## 6 落地顺序（★ 一次只拆一类，拆完跑全套 533 项）

```
① prompts/      纯文本 · 收益最高 · 零逻辑风险
② interface.py  ★ 先立它 —— 立完立刻就有"能不能到达"的检查（守卫 ③）
③ params/       只放【刻】· 配守卫 ①
④ state/ reports/ characters/      纯搬家（★ 注意下面的路径地雷）
⑤ engine/ 内部分文件               ★ 最后，且只改 import
```

**⇒ 纪律：一次只拆一类。**
**⇒ 今晚所有事故都是"一次改一处，而那一处没接上"—— 一次拆六类，出问题就分不清是哪一类。**

## 7 ⚠️ 三个具体地雷（我已核过）

```
① `api_client` 按【向上三级】找 `.env`
     ⇒ 移 `api_client.py` 或 `.env` 必须同时改那三行
② `test_*.py` 写死了 `../characters/...` 这类相对路径
     ⇒ 移目录会红一片 —— 先 grep 一遍再动
③ ★ 回测脚本（`_case_feed.py` · `_twocards.py`）读的就是这些路径
     ⇒ ★ 动之前确认【没有作业在跑】
```

## 8 一条反向纪律

**⇒ 接口要少而稳，不是每个函数都包一层。**

$$\text{今晚的病是【接线】}\ \Longrightarrow\ \textbf{接口越少 ⇒ 接线点越少 ⇒ 出错面越小}$$
