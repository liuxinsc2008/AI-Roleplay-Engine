## 一、依恋层：这个状态机「不听什么」

> 以下讲的是 `attachment_sm`（关系状态层）。
> 主权层与编排层的设计见 `CONTRACTS.md`。

模型第 6.3 节第 1 条写得很明白：

> 依恋类型是倾向，不是状态，不能被话术触发或安装。

所以这台状态机**刻意不接受「台词驱动」**。你不能靠一句情话来推进角色的 `Z₁`。
唯一能移动坐标的通道是 `expose_need()` —— 角色暴露一次需求，
然后由**对方的样本**决定这次需求有没有被接住。

这是模型的本来机制（0.3）：

> 对他好 → 需求被接住 → Z₁ 向负移动
> 对他不好 → 需求被忽视、贬低、惩罚 → Z₁ 向正移动

一个人的 `Z₁` 移动了多少，取决于他历史上被如何对待，
而不取决于对方此刻说了什么漂亮话。状态机照此实现。

> **主权层的补充（CONTRACTS §0.1）**：`expose_need()` 接受可选的 `verdict` 闸门。
> 传了闸门时，**对方接住了需求 ≠ 角色接受** —— 样本只是裁决材料，不是命令。
> 不传（`verdict=None`）时保持纯依恋动力学（向后兼容）。

### 为什么双方都要建模

因为「对他好/不好」不是主体自己能决定的。如果只建模主体，
那就得由使用者来投喂「这次对方接住了吗」——那等于把对方的行为变成了一个外部旋钮，
使用者可以随意拧。所以 `Counterparty` 是一个有自己行为模式的实体：

| 对方模式 | 对应模型 | 行为 |
|---|---|---|
| `RELIABLY_ACCEPTING` 稳定承接 | 3.2 推导1 | 需求总被接住 |
| `INTERMITTENT` 间歇回应 | 3.2 推导2 | 有时接住，有时忽视（**不含惩罚**） |
| `SYSTEMATIC_PUNISHING` 系统高压 | 3.2 推导3 | 忽视、贬低、惩罚 |
| `REJECT_CONTROL` 拒绝+控制 | 3.2 推导4 | 冷热暴力交替 |
| `ABSENT` 无对象 | 2.4.7 | 无人承接 |

### 四类推导必须落在各自说的象限

这是实现过程中发现的一个真实错误，值得单独写出来。

模型 3.2 对四条推导链分别给出了明确坐标。第一版实现在
`INTERMITTENT`（推导2）上混入了惩罚项，比例是 2 接住 : 1 忽视 : 1 惩罚。
结果是角色**滑向了疏离型**，与模型写死的 `Y>0, X<0 → 焦虑型` 直接矛盾。

原因在于：推导2 的机制是「**不确定**」，不是「系统性惩罚」。

> 有时接住，有时忽视/惩罚 → 结果不确定，我必须持续确认/试探
> → 过度激活依恋系统。Y>0, X<0 → 焦虑型

接住的比例必须高到足以维持希望（「我乖一点会不会好一点」）。
一旦惩罚占的比重过大，**去激活机制就会盖过过度激活机制**，
系统滑向疏离而不是焦虑。惩罚极属于推导3和推导4，不属于推导2。

修正后四条推导全部落在模型指定的象限：

| 推导 | 模型要求 | 实现结果（12 轮后） |
|---|---|---|
| 1 稳定回应 | 安全型 | `X=-3.6, Y=-4.8` 安全型 ✓ |
| 2 间歇回应 | **Y>0, X<0** 焦虑型 | `X=-2.4, Y=+3.2` 焦虑型 ✓ |
| 3 系统高压 | Y<0, X>0 疏离型 | `X=+8.4, Y=-6.0` 疏离型 ✓ |
| 4 拒绝+控制 | X>0, Y>0 恐惧型 | `X=+6.6, Y=+10.0` 恐惧型 ✓ |

`test_derivation_2_intermittent_to_anxious` 锁定了这一条，防止回归。

顺带说明一个实现细节：推导2 的 `ignored` 分支给 `Y` 的增量与推导文本不一致（实现取值更高，具体数值不公开）。
因为「被接住」会带来 `Y` 的回落，但「不知道下次会不会被接住」的持续叠加
会让过度激活不断升级，净效应是 `Y` 上升。这正是 2.11 所说的耦合 ——
`X`、`Y` 会反过来牵动 `Z₁`，不是 `Z₁` 单向牵动它们。

而且它用的是**滑动窗口统计**而不是单次反应 —— 因为 4.1 说：

> 熟悉 = 可预测的样本库。单次行为不能判断有毒没毒，行为分布可以判断。

这就是「稳定没法表演，只能持续」（6.2-2）在代码里的样子：
样本窗口填不满，稳定性就判定不出来，边界解就永远触发不了。

### 版本要求

| | 最低 | 说明 |
|---|---|---|
| Python | 3.10+ | 用到 `dataclasses` 与 `X \| None` 写法 |
| Node | **22.6+** | 靠原生类型擦除直接跑 `.ts`，不编译 |

Node 版本不够会报语法错误，`check-env.cmd` 会直接提示。

### Windows 上的三个坑

**1. 别用 `node --test`。** 它会为每个测试文件 spawn 子进程并用管道收输出，
在受限环境下会被拒（`EPERM: spawn`）。测试文件因此自带同进程运行器：

```powershell
node attachmentSm.test.ts            # ← 用这个
node --test attachmentSm.test.ts     # ← 不要
```

**2. `.ps1` 可能被执行策略挡住。** 系统默认禁止运行未签名脚本。
用 `.cmd` 包装器绕过（`-ExecutionPolicy Bypass` 只对本次调用生效，不改系统设置）：

```powershell
.\check-env.cmd     # ← 用这个
.\check-env.ps1     # ← 可能报「未进行数字签名」
```

**3. `WindowsApps\python.exe` 是假的。** 那是微软商店的占位符，运行它只会
弹「去商店安装」的提示，不是真 Python。真 Python 装在
`%LOCALAPPDATA%\Programs\Python\Python3xx\`。

`check-env.ps1` 刻意写成纯 ASCII —— Windows PowerShell 5.1 会按系统
ANSI 代码页（中文机器上是 GBK）读 `.ps1`，非 ASCII 内容会乱码甚至破坏解析。

## 五、三条分化路径（状态机的主要输出）

雪崩依恋态是**分化点，不是终点**（2.5 / 2.6）。从同一次雪崩出发：

```
                    ┌─ 对象极度稳定 ──→ 正常黏人
                    │   Z₁=-10 保持，Y→-10（病态占有降低）
雪崩依恋态 (Z₁=-10) ─┼─ 对象不稳定 ────→ 极度回缩
                    │   Z₁=+10，X 极高（比原疏离更极端）
                    └─ 无对象/单相思 ─→ 单恋雪崩依恋态 → 退回
                        Z₁ 逐步向 0 滑回
```

演示 5 会把这三条路径一次跑完，打印坐标轨迹。

## 六、几个刻意的设计决定

### 1. 雪崩依恋态在四象限里「看起来像安全型」

雪崩后坐标是 `X=-0.5, Y=-1.0`，几何上落在第三象限。
但把它标成「安全型」是误读。

所以 `Snapshot.style_label` 会输出
`安全型（仅几何投影，不表类型）`，并且 `as_dict()` 里带一个
`style_is_structural: false` 字段。理由就是 6.3-2：

> 类型不是位置，一个人可以在不同关系里处于不同象限。

### 2. 强行消解会返回 `True`，但模型不鼓励

`force_suppress()` 会成功执行并更新坐标（2.5.1 确实描述了这条路径），
但它把系统推向更坏的位置：`Z₁` 拉到 +10、`X` 拉得比原疏离更高、`Y` 锁得更死。

源码和文档都明确标注这是**补充情况，非通用路径**（2.5.1 边界声明 / 6.3-13）。
它不返回「失败」，因为模型承认它会发生；但它不返回任何「成功」语义。

### 3. 极端层是风险信号，不是结局

2.4.8 的控制分层里，极端层是囚禁/自残/威胁/毁灭。
本实现不把它做成一个可到达的「结局分支」，也不做浪漫化处理。

### 4. 阈值全部是模型设定刻度

所有阈值都是 1.3 说的「模型设定刻度，
不是理论推导公理，也不是实证临界值」。它们在实现里全部提成常量，
便于按人群分布重新校准 —— **具体取值不在本说明中公开。**

### 5. 时间尺度是近似的

2.4.7 明说「时间尺度未在模型中固定」。`regress_from_unrequited()`
用的是固定步长，日志里也如实声明了这一点，没有假装它是模型给出的数值。

## 七、边界声明

本实现是**解释框架的代码化**，不是临床工具。

- 不用于诊断他人，不用于操纵关系（6.3-4）
- 术语（雪崩依恋态、单恋雪崩依恋态等）仅为状态坐标命名，
  不表示赞赏、贬低或临床判断（6.3-9）
- 「不允许抽离」「高浓度占有」在现实中是**边界风险信号**，不是关系理想
- 样本/授权是操作性隐喻，不是既有学术术语（6.3-5）
- 所有阈值为模型设定刻度，可校准（6.3-6）
- 两个参考系不可混用：O 系原点 = 婴儿，S 系原点 = 极度安全态（6.3-7）

## 八、一个诚实的提醒

状态机把模型做成了可执行的，这本身会带来一个模型作者已经警告过的风险：

> 把关系当工程，是用造成问题的机制去解决问题。（6.2-4）

如果这台状态机被用来「攻略」某个人 —— 刻意制造样本、表演稳定、等待雪崩 ——
那它实现的就是 6.2 里被否定的东西。模型给的答案是：

> 真实情况是「我们共同移动」。

代码无法强制使用者怎么用。但 `Counterparty` 的滑动窗口至少保证了一件事：
**假装稳定会在样本窗口里露馅。**
